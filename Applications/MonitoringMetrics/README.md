# MonitoringMetrics

Self-hosted metrics storage with VictoriaMetrics single-node and vmauth.
Traefik provides HTTPS ingress, cert-manager manages the certificate, and
Longhorn provides persistent storage. Collection is a separate application,
[MonitoringAgent](../MonitoringAgent/README.md).

## Contents

```text
base/                     Namespace, resource quota and network policies
components/
  _application/           VictoriaMetrics StatefulSet and Service
  _auth/                  vmauth Deployment, Service and authentication config
  _ingress/               Certificate and Traefik IngressRoutes
overlay/
  _SAMPLE/                Complete public template with sample data
    configs/              Sample vmauth users and path permissions
    generators/           ConfigMap and Secret generators
    patches/              Certificate, ingress, storage and quota settings
    secrets/              Non-sensitive placeholder credentials
    transformers/         Images, labels and replica counts
  <environment>/          Local configuration, ignored by Git
```

## Features

- Prometheus-compatible Remote Write and query APIs on one HTTPS hostname.
- Separate writer tokens, Grafana read credentials and a telemetry token.
- A server-selected cluster label for each writer.
- Allowlisted API paths, internal-IP ingress restrictions and default-deny
  network policies. VictoriaMetrics has no direct ingress.
- Compressed storage with a default retention of 90 days.
- A 50 GiB initial PVC and a 10 GiB minimum-free-space threshold.

This is a single-instance backend. Storage replication does not provide
application-level high availability or replace a backup. Scrape intervals are
configured in the collector. This deployment does not downsample older data.

## Prerequisites

- Kubernetes, `kubectl` and standalone `kustomize`.
- A CNI that enforces Kubernetes NetworkPolicies.
- Longhorn with the `longhorn-retain` StorageClass, or an equivalent class
  configured in your overlay. Enable expansion and reserve capacity for
  storage replicas, snapshots and rebuilds.
- Traefik with its CRDs, the `websecure` entrypoint and cross-namespace
  middleware references enabled.
- The repository's `traefik-system/chain-default` middleware, including its
  RFC1918 allowlist. If your installation uses different names or labels,
  patch both IngressRoutes and the Traefik NetworkPolicy selector.
- cert-manager and a ready ClusterIssuer. The supplied certificate references
  `letsencrypt-production-default`. Patch the issuer reference if needed.
- Internal DNS pointing the chosen hostname to Traefik, with firewall access
  from the intended writers and query clients.

The shared Traefik middleware restricts source IPs. Authentication and
read/write permissions are enforced by vmauth. Do not add an interactive browser
login flow to machine-to-machine endpoints.

## Deployment

Run the following commands from `Applications/MonitoringMetrics`.

### 1. Create Your Overlay

```sh
cp -r overlay/_SAMPLE overlay/my-environment
umask 077
chmod 600 overlay/my-environment/secrets/secret-monitoring-metrics-auth.env
```

Use an overlay name that does not start with an underscore. Such overlays and
ordinary `.env` files are ignored by this repository. Git ignore rules are not
encryption. Never force-add real credentials or rendered Secret manifests.

The sample has the same Kustomize structure as an environment overlay. Its
credentials are public placeholders and must be replaced before deployment.

### 2. Configure Secrets and Users

Open `overlay/my-environment/secrets/secret-monitoring-metrics-auth.env` and
replace every placeholder with an independent credential, preferably 32
randomly generated bytes encoded as hex. The sample contains four writers:

```dotenv
WRITER_CLUSTER_A_TOKEN=<unique-random-writer-token>
WRITER_CLUSTER_B_TOKEN=<unique-random-writer-token>
WRITER_CLUSTER_C_TOKEN=<unique-random-writer-token>
WRITER_CLUSTER_D_TOKEN=<unique-random-writer-token>
GRAFANA_USERNAME=grafana-reader
GRAFANA_PASSWORD=<unique-random-reader-password>
TELEMETRY_TOKEN=<unique-random-telemetry-token>
```

Then edit `configs/auth.yml`. Rename `cluster-a` through `cluster-d` to your
cluster identifiers and keep each token reference aligned with its key in the
private `.env` file. Give only the matching token to each collector.

There is no fixed cluster count. Add or remove writer entries and their Secret
keys together. Use environment-variable-compatible key names. Preserve the
template's path restrictions and authorization-header stripping. Keep Grafana
and telemetry credentials separate from writer credentials. Keep the generated
name suffixes enabled so Kustomize updates workload references and triggers a
rollout when the inputs change.

### 3. Configure Patches and Transformers

| File | Configuration |
| --- | --- |
| `patches/certificate.yaml` | Certificate DNS name and organization |
| `patches/ingressroute-write.yaml` | The same hostname for Remote Write |
| `patches/ingressroute-query.yaml` | The same hostname for queries and telemetry |
| `patches/pvc.yaml` | Initial PVC capacity |
| `patches/resource-quota.yaml` | Namespace quota, including rollout headroom |
| `transformers/images.yaml` | Pinned VictoriaMetrics and vmauth versions |
| `transformers/labels.yaml` | Deployment labels |
| `transformers/replicas.yaml` | Keep VictoriaMetrics at one replica |
| `kustomization.yaml` | Version label and additional overlay patches |

Replace `metrics.example.com` in all three relevant patches. Keep the existing
path and HTTP-method restrictions when changing the hostname.

Add overlay patches for a different StorageClass, issuer, retention period,
resource allocation or network layout. Keep reusable base files free of
environment-specific values. Do not scale the single-node VictoriaMetrics
StatefulSet to multiple replicas, each would have separate data.

### 4. Validate and Deploy

Confirm the target Kubernetes context before applying anything:

```sh
kubectl config current-context
set -o pipefail
kustomize build overlay/my-environment > /dev/null
kustomize build overlay/my-environment | kubectl apply -f -
```

Rendered private overlays contain credentials, even when base64 encoded.
Do not print them into logs or save them in shared temporary files.
The validation command checks rendering, not live cluster compatibility.

Check readiness without displaying Secret contents:

```sh
kubectl -n monitoring-metrics rollout status statefulset/victoriametrics
kubectl -n monitoring-metrics rollout status deployment/vmauth
kubectl -n monitoring-metrics get pods,pvc
kubectl -n monitoring-metrics wait --for=condition=Ready certificate/monitoring-metrics --timeout=180s
```

### 5. Connect Clients and Verify Access

| Client | URL example | Authentication |
| --- | --- | --- |
| Metrics collector | `https://metrics.example.com/api/v1/write` | Its own writer bearer token |
| Grafana Prometheus datasource | `https://metrics.example.com` | Dedicated reader Basic Auth |
| Backend telemetry collector | `https://metrics.example.com/telemetry/victoriametrics/metrics` | Telemetry bearer token |
| vmauth telemetry collector | `https://metrics.example.com/telemetry/vmauth/metrics` | Telemetry bearer token |

Keep TLS verification enabled and use server-side requests in Grafana.
Store client credentials in the respective application's private Secret input,
not in public manifests, datasource files or URLs.

Verify that writers can ingest but cannot query, and that the Grafana reader
can query but cannot write. Missing or invalid credentials must be denied.
Confirm that the stored cluster label is server-selected, including when a
test client submits a conflicting label. Test that non-internal sources and
direct access to VictoriaMetrics from unapproved Pods are blocked.

## Network Requirements

| Source | Destination | Protocol / destination port | Purpose |
| --- | --- | --- | --- |
| Collectors and Grafana | Traefik HTTPS endpoint | TCP 443 | Writes, queries and telemetry |
| Traefik Pods | vmauth | TCP 8427 | Authenticated proxy |
| vmauth | VictoriaMetrics | TCP 8428 | Backend writes, queries and metrics |
| vmauth | Its own loopback listener | TCP 8426 | Internal telemetry |
| Kubelet | vmauth / VictoriaMetrics Pods | TCP 8426 / 8428 | Health probes |
| Backend Pods | Cluster DNS | UDP/TCP 53 | Name resolution |
| cert-manager | Issuer and DNS-provider APIs | Usually TCP 443 | Certificate lifecycle |

Traefik's Service can translate external port 443 to a different container port.
Client egress rules must account for the actual target port and the CNI's NAT
behavior. Certificate issuance may require additional access depending on the
issuer and challenge method.

The central backend does not initiate connections to remote clusters.
Collector discovery and scrape ports belong to the separate collector
deployment. Ports 8426, 8427 and 8428 must not be exposed as external ingress.

## Storage and Maintenance

### Resource Budget

| Component | CPU request / limit | Memory request / limit |
| --- | --- | --- |
| VictoriaMetrics | 0 / 1 CPU | 0 / 1Gi |
| vmauth | 0 / 200m | 0 / 128Mi |

CPU and memory requests are explicitly zero, so these containers reserve no
scheduling capacity. Omitting requests while retaining limits would default
requests to the limits. This increases overcommit and eviction risk under node
pressure. PVC storage requests remain unchanged. These limits are small-cluster
starting budgets. Memory depends on active series, churn and concurrent
queries, not just Pod count. Check loaded operation, query latency, throttling
and OOM restarts before tightening limits further. Idle usage does not predict
ingestion capacity. Keep quota headroom for a second vmauth Pod during rollout.

### Capacity and History

The configured retention is 90 days for incident investigation and short-term
trends. Use 180 days only when six-month comparisons justify the additional
storage. Halving retention roughly halves retained
sample payload at a steady ingestion rate, not necessarily all disk use, and
does not halve ingestion CPU or memory. Lowering retention can delete existing
history. Make that change deliberately through an overlay patch.

The 50 GiB default is a starting capacity, not a guarantee that 90 days will
fit. Measure daily growth, active series and ingestion rate before projecting
retention capacity. Monitor the 10 GiB free-space reserve, writes stop when the
configured threshold is reached.

VictoriaMetrics removes expired data during retention maintenance, not exactly
at each sample's expiry time. Longhorn snapshots and backups have independent
retention. This deployment does not configure backups or alerts.

For expansion, increase the existing PVC and update the overlay. A StatefulSet
claim-template change alone does not resize an existing PVC, and Kubernetes
restricts updates to that template. Plan any required StatefulSet recreation
while preserving its PVC. Volumes cannot be shrunk.

For credential rotation, update the server and matching client's private inputs,
then apply both overlays in a coordinated change. A direct replacement has no
automatic overlap period and can briefly interrupt access. Verify writes or
queries afterwards. Never delete the data PVC to repair authentication or
rollout failures.

## Troubleshooting

- **PVC pending:** Check the StorageClass, Longhorn capacity and PVC events.
- **vmauth fails to start:** Check that the generated Secret exists and every
  referenced environment variable has a matching key.
- **HTTP 401/403:** Check the client identity, allowed paths and the source IP
  seen by Traefik. An internal hostname alone does not ensure an RFC1918 source.
- **HTTP 404:** Check the hostname, method and path against the IngressRoutes.
- **HTTP 502/503 or timeouts:** Check Pod readiness, Service endpoints,
  NetworkPolicy selectors and available disk space.
- **Certificate not ready:** Check the issuer, DNS and challenge status.
  Do not bypass certificate verification.

Inspect logs locally and redact credentials or infrastructure details before
sharing them.
